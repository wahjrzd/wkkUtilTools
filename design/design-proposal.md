# wkk.tools 视觉方案 v6

日期：2026-11-11。状态：设计提案，待评审；未实现网站功能。

## 设计方向

采用用户选择的清透轻盈方向：浅灰白背景、白色工作区、蓝色操作强调。暂用名称 wkk.tools，可替换。

- 背景：#F5F7FB
- 工作区：#FFFFFF
- 主文字：#172641
- 主色：#356AF3
- 浅色强调：#EAF1FF
- 分隔线：#E7ECF4
- 字体：中文使用 Microsoft YaHei UI；英文使用 Segoe UI；代码、时间数据使用 Consolas。实现时可根据可用字体调整。
- 桌面布局：80 px 顶部横向导航；左侧为品牌及工具入口，右侧为本地处理状态与外观入口。取消侧栏，1600 px 画布下内容左右各留 64 px，编辑区占主要空间。
- 视觉重点：宽敞编辑器、清晰的输入输出层次、时间结果的大号数字；不添加营销首页。

## JSON 格式化

按用户要求，页面仅保留一个可编辑文本框和一个「格式化」按钮。移除工作区上方的标题和说明，文本框紧接顶部导航下方；按钮位于文本框下方左侧，与文本框左边缘对齐。移除左右输入输出分栏，以及缩进、换行、复制、下载、压缩、清空、转义等操作入口。

用户在文本框中粘贴 JSON，点击格式化后，直接在同一个文本框内替换为带真实换行及 Tab 缩进的可读 JSON。固定使用 CRLF 换行，不暴露配置选项。普通键盘选择、复制、粘贴仍可使用。

格式化失败时保留原文，在文本框下显示简短的错误及位置提示，不新增操作控件。空文本框用占位文案提示粘贴 JSON。保持数字原始精度，避免改变字符串字段内容。

效果图展示同一文本框中的格式化完成状态；仅为静态设计，尚未实现功能。
## 时间戳转换

按用户要求，将页面改为始终可见的三行，不再使用双向转换标签页，不添加页面大标题。

第一行：实时时间。显示本地日期时间、星期及当前 Unix 时间戳，每秒刷新。以只读文字说明系统时区，不提供选择器。

第二行：Unix 时间戳转字符串。横向排列时间戳输入框、转换按钮和只读日期字符串结果。输入自动识别秒或毫秒，不增加单位选择器；输入框下显示「已识别为秒」或「已识别为毫秒」。常见 10 位整数按秒处理、13 位整数按毫秒处理，负号不计入位数。其他长度或小数存在歧义时提示无法确定单位，不静默猜测。

第三行：字符串转 Unix 时间戳。横向排列日期字符串输入框、转换按钮和只读 Unix 结果。第二、三行互相独立，实时时钟刷新不会覆盖用户输入或转换结果。

采用浏览器运行环境的系统时区解析和显示日期时间。没有时区设置。字符串转 Unix 的输出仍明确标注为秒。Unix 转字符串若毫秒部分非零则显示 YYYY-MM-DD HH:mm:ss.SSS，否则显示 YYYY-MM-DD HH:mm:ss，避免丢失毫秒信息。字符串转 Unix 接受 YYYY-MM-DD HH:mm:ss 格式。支持合法负时间戳，对空输入、非法日期及越界值给出就地错误提示，保留原始输入。对系统时区内夏令时导致的重复或不存在时间给出明确提示。

效果图以 Asia/Singapore（UTC+08:00）为静态示例：1794362400 秒和 1794362400000 毫秒均对应当地 2026-11-11 10:00:00。实际页面应读取系统时区；效果图中的实时时间不会运行。
## 适配与交互

窄屏时顶部横向导航精简为品牌与工具切换，JSON 单个文本框随屏幕宽度自适应，格式化按钮保持可见。时间戳页保留三个分区的顺序，窄屏时每个转换行内部的输入、按钮、结果纵向排列。

主操作使用蓝色；复制成功用短暂状态反馈。键盘焦点明确，错误不仅依赖颜色表达。正式实现需检查文字对比度，尤其辅助文字。

建议所有转换在浏览器本地执行，无需账号。页面内“本地处理”是待实现的产品要求。
